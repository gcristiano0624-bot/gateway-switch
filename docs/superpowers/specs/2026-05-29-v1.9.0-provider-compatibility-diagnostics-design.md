# Gateway Switch v1.9.0 Provider Compatibility Diagnostics Design

## Goal

Gateway Switch v1.9.0 turns the v1.8.8 Volcengine DeepSeek hotfix into a broader compatibility and diagnostics layer.

The release must include:

- Provider compatibility strategy profiles.
- Route diagnostics for Claude and Claude Code usage.
- Redacted payload preview for Anthropic-to-Chat conversion.
- App install-source/runtime-location warning for DMG or temporary-volume execution.
- Tests and documentation for the new compatibility behavior.

## Scope

### Provider Compatibility Strategy

Add a backend compatibility profile for each provider/model pair. The profile exposes:

- `system_to_user`: merge Anthropic system instructions into the first user message.
- `tool_to_user`: convert Anthropic tool results into user text.
- `disable_tools`: reserved for providers that cannot accept tool schemas.
- `strip_unsupported_params`: reserved for providers that reject optional request parameters.
- `direct_provider_safe`: whether Claude Code Direct Provider should be allowed.
- `strategy_id`: stable label such as `standard_anthropic`, `openai_chat`, or `volcengine_deepseek_coding`.

For v1.9.0 the initial automatic policy is:

- Volcengine / Ark / DeepSeek coding routes use `volcengine_deepseek_coding`.
- Other routes keep `standard_anthropic` or `openai_chat` derived behavior without changing existing request behavior.

### Route Diagnostics

Add a Tauri command that returns route diagnostics for configured Claude routes:

- Provider and upstream model.
- Selected compatibility strategy.
- Whether Gateway Route is recommended.
- Whether Direct Provider is safe for Claude Code.
- Human-readable reasons and warnings.

The frontend should display diagnostics in the Claude Code page and Provider/route context, without changing the sidebar structure.

### Payload Preview

Add a safe preview command that converts a sample Anthropic Messages request into the upstream Chat payload shape for a chosen route.

Rules:

- Do not send the preview to the upstream provider.
- Redact secrets.
- Use a small fixed sample request.
- Show role list and JSON preview.

### Runtime Source Check

Add an app source report:

- `bundle_path`
- `is_applications`
- `is_dmg_volume`
- `is_temp_volume`
- `severity`
- `summary`
- `recommendation`

The frontend should warn when the app runs from `/Volumes`, `/private/tmp`, or `/tmp`, because this can poison launchd/watcher paths.

## Non-Goals

- Do not implement live request replay in v1.9.0.
- Do not add a full auto-updater.
- Do not rewrite the Codex gateway into the same profile layer yet.
- Do not migrate existing provider records destructively.

## Testing

Add tests for:

- Volcengine DeepSeek profile selection.
- Standard provider profile selection.
- Route diagnostics for Direct Provider safety.
- Payload preview role conversion.
- Runtime source classification for `/Applications`, `/Volumes`, and `/tmp`.

## Release Plan

- Version bump to `1.9.0`.
- Update `README.md`, `README_EN.md`, `CHANGELOG.md`, `docs/project.md`.
- Add release notes under `docs/release-1.9.0-provider-compatibility-diagnostics.md`.
- Run `pnpm build`, `cargo test --locked`, and `pnpm tauri build`.
- Package and release with `macos-dmg-github-release` after implementation validation.

# v1.13.0 Unified Loop Guard Design

## Goal

Gateway Switch must prevent repeated AI text and repeated tool-call loops across Claude Desktop, Claude Code, and Codex without truncating valid long-form output.

## Scope

- Add a shared `loop_guard` module used by Claude Gateway and Codex Gateway.
- Detect duplicate text blocks by normalized rolling sentence/paragraph fingerprints instead of output length.
- Suppress duplicate text chunks while allowing new content to continue streaming.
- Detect repeated tool-call fingerprints so future routing code can replace duplicate tool calls with idempotent guard results.
- Record compact diagnostic summaries in request logs.
- Tune risky Chat-provider defaults so Xiaomi MiMo no longer defaults to strict Codex tool calls.

## Non-Goals

- No blind hard-stop based only on output length.
- No automatic upstream retry loops.
- No token-consuming real replay.
- No user-visible interruption unless duplicate content is actually suppressed.

## Behavior

### Text Guard

Each streamed text delta is split into normalized sentence-like segments. The guard tracks segment hashes and rolling text similarity. The action is:

- `Pass`: content is new and should be streamed.
- `Suppress`: content is repeated and should not be forwarded.

Long reports pass because their segment fingerprints change. Repeated planning text such as `Now let me fetch...` is suppressed after repeated hits.

### Codex Gateway

Codex streaming converts Chat Completions SSE into Responses SSE. The guard runs before emitting `response.output_text.delta`. Suppressed duplicate text is omitted from `full_text`; diagnostics are written to request logs.

### Claude Gateway

Claude streaming and Chat fallback run the same text guard before emitting Anthropic text deltas. Suppressed duplicate chunks are omitted while the stream continues for new information.

### Diagnostics

Request logs include summaries such as:

- `loop_guard: suppressed_text=12 repeated_segments=4`
- `tool_trace: ...; loop_guard: ...`

Diagnostics Center can surface these warnings without needing schema changes.

## Testing

- Unit tests for repeated text suppression.
- Unit tests that long non-repeating text passes.
- Claude Gateway stream guard test.
- Codex Gateway stream guard test.
- Existing large body, fallback, and tool-call tests must continue passing.

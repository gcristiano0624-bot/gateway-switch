# Gateway Switch v1.14.0 Provider Wizard and One-Click Health Check Design

## 1. Goal

v1.14.0 adds a guided Provider setup flow and a one-click health check system on top of the existing Provider Presets, route diagnostics, and Gateway health commands.

The design must preserve the current runtime compatibility architecture:

- Providers remain the shared upstream registry.
- Claude and Codex routes remain separate route tables.
- Provider compatibility policies remain explicit and visible.
- Diagnostics remain local-first and redacted.
- Real token-consuming checks remain opt-in.

## 4. Backend Design

### 4.1 New Module: `provider_wizard.rs`

Responsibility:

- Convert a preset or custom input into a safe draft.
- Validate required fields.
- Create or update Provider.
- Optionally create or update Claude/Codex routes.
- Upsert recommended compatibility policy.
- Return an application report.

Suggested file:

- `src-tauri/src/provider_wizard.rs`

### 4.2 New Module: `health_check.rs`

Responsibility:

- Run Quick Check across runtime, gateways, providers, routes, and policies.
- Normalize health check result shape.
- Map HTTP/network/config errors to suggested actions.
- Produce aggregate report for UI and export.

Suggested file:

- `src-tauri/src/health_check.rs`

### 4.6 Health Check Algorithm

#### Step 1: Runtime Checks

- Verify database path exists.
- Verify settings path can be loaded.
- Verify there is at least one enabled Provider.

#### Step 2: Local Gateway Checks

Reuse:

- `probe_gateway_health`
- `check_codex_health`

Outputs:

- `gateway:claude`
- `gateway:codex`

#### Step 3: Provider Checks

For each selected Provider:

- Build `GET {openai_base_url}/models`.
- Add auth header if API Key exists.
- Timeout should be short, recommended 8 seconds.
- Record HTTP status and latency.

Mapping:

- 2xx: pass
- 401/403: fail, invalid credential or auth header
- 404: warn/fail, likely wrong Base URL or unsupported `/models`
- 408/timeout: fail, network or firewall
- 429: warn, quota/rate limit
- 5xx: warn/fail, upstream unstable

If Provider has `anthropic_base_url`:

- v1.14.0 Quick Check should not call `/v1/messages`.
- Only validate URL shape and policy consistency.

#### Step 4: Route Checks

Claude route checks:

- Route enabled.
- Provider exists.
- Provider enabled.
- `claude_alias` non-empty.
- `upstream_model` non-empty.
- If Provider is chat-only, verify strategy forces Chat fallback.

Codex route checks:

- Route enabled.
- Provider exists.
- Provider enabled.
- `codex_model` non-empty.
- `upstream_model` non-empty.
- If Provider is non-OpenAI official, verify Codex Chat fallback policy.

#### Step 5: Compatibility Policy Checks

For risky providers:

- Xiaomi, Volcengine, DeepSeek, Moonshot, Qwen should prefer Gateway Route for Claude Code.
- Chat-only providers should have system/tool role conversion enabled where appropriate.
- `codex_strict_tool_calls` should not be forced for Xiaomi MiMo by default.

#### Step 6: Score Aggregation

Each check returns a score:

- pass: 100
- warn: 70
- fail: 20
- skipped: 50

Weighted aggregate:

- Runtime: 10%
- Gateways: 20%
- Provider connectivity: 35%
- Routes: 25%
- Policies: 10%

Clamp rules:

- Any local Gateway fail caps total score at 70.
- Any selected Provider auth fail caps total score at 50.
- No enabled Provider caps total score at 30.

### 4.7 Error-to-Action Mapping

Create helper:

```rust
fn suggest_health_action(check: &ProviderHealthCheck) -> Option<DiagnosticsAction>
```

Mappings:

- 401/403 -> "Check API Key and auth scheme"
- 404 -> "Verify Base URL does not duplicate `/v1` and supports `/models`"
- 429 -> "Check quota or wait before retrying"
- 5xx -> "Provider service may be unstable"
- network -> "Check network, proxy, DNS, or endpoint"
- missing provider -> "Recreate route or choose a valid Provider"
- disabled provider -> "Enable Provider"
- missing route -> "Create recommended route from Provider Wizard"
- unsafe direct provider -> "Use Gateway Route instead of Direct Provider"

### 4.8 Redaction

Use existing redaction helpers from `compatibility.rs` where possible.

Redact:

- API keys
- Authorization values
- Bearer tokens
- JWT-like values
- Long payloads
- Provider raw error body beyond 1200 chars

## 6. Route Creation Rules

### 6.1 Claude Route

Default fields:

- `id`: `wizard-{provider_id}-claude`
- `claude_alias`: preset `recommended_claude_alias`
- `display_name`: `{Provider Name} Claude`
- `provider_id`: selected Provider id
- `upstream_model`: wizard upstream model
- `enabled`: true

### 6.2 Codex Route

Default fields:

- `id`: `wizard-{provider_id}-codex`
- `codex_model`: preset `recommended_codex_model`
- `display_name`: `{Provider Name} Codex`
- `provider_id`: selected Provider id
- `upstream_model`: wizard upstream model
- `enabled`: true

### 6.3 Conflict Handling

If route id exists:

- If `update_existing` is true, update it.
- If false, skip route and add warning.

If alias/model exists under another route id:

- Show warning in preview.
- Require user confirmation to update.

## 7. Compatibility Rules

Provider Wizard must not bypass existing policy logic.

Required behavior:

- Always show recommended policy before applying.
- Preserve existing policy if user chooses not to update strategy.
- Apply preset policy only after explicit confirmation.
- For chat-only providers, prefer Gateway Route.
- For risky providers, Direct Provider remains gated by the existing checkbox.

No required DB migration for v1.14.0.

- Existing Provider records remain valid.

Potential future migration:

## 11. Risks

### 11.1 Provider `/models` Incompatibility

Some Provider endpoints may not support `/models`.

Mitigation:

- Treat 404 as warning when route config is otherwise complete.
- Explain that Quick Check validates connectivity, not full model generation.

### 11.2 False Healthy State

`/models` can pass while chat completion fails.

Mitigation:

- Clearly label Quick Check as non-token connectivity check.
- Reserve Deep Check for explicit opt-in.

### 11.3 Route Overwrite

Wizard could overwrite user route choices.

Mitigation:

- Preview conflicts before apply.
- Require `update_existing=true`.
- Return warnings in report.

### 11.4 API Key Exposure

Health checks may include upstream errors that echo credentials.

Mitigation:

- Run every error summary through redaction.
- Never export full request headers.

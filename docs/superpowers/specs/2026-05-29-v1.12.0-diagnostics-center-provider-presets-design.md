# Gateway Switch v1.12.0 Unified Diagnostics Center and Provider Presets Design

## Goal

Gateway Switch v1.12.0 advances the v1.10.0 compatibility control plane into a product-facing operations console. It combines the planned v1.11.0 Unified Diagnostics Center with the v1.12.0 Provider Preset and strategy-template layer so the app can answer two questions quickly:

- What is unhealthy across Claude Desktop, Claude Code, Codex, Codex++, Providers, and installation/runtime?
- What preset or compatibility strategy should the user apply next?

## Scope

### 1. Unified Diagnostics Center

Add a new app page that aggregates health across existing subsystems.

Backend requirements:

- Add serializable diagnostics models:
  - `UnifiedDiagnosticsReport`
  - `DiagnosticsSection`
  - `DiagnosticsAction`
  - `DiagnosticsMetric`
- Add a Tauri command `get_unified_diagnostics`.
- Aggregate existing data only; do not introduce risky side effects.
- Include sections for:
  - Claude Desktop
  - Claude Code
  - Codex Gateway
  - Codex++
  - Providers
  - Install / Runtime
- Each section returns:
  - status: `healthy`, `attention`, `degraded`, or `critical`
  - score from 0 to 100
  - summary
  - metrics
  - actions
- Overall status is derived from the lowest major section status and average score.
- Add a redacted copyable diagnostics bundle command `export_unified_diagnostics_bundle`.

Frontend requirements:

- Add a new `Diagnostics` page under the System sidebar group.
- Show a top-level score/status card.
- Render subsystem cards with metrics and action buttons or action descriptions.
- Include recent failure aggregation by provider/status/surface.
- Include a copy/export diagnostics bundle button.

### 2. Provider Health and Failure Summary

Use existing v1.10.0 request snapshots and route diagnostics to summarize likely problems.

Backend requirements:

- Aggregate failed snapshots by provider, status code, and surface.
- Derive simple recommendations:
  - 400 with role/system errors -> enable `system_to_user` and prefer Gateway Route.
  - tool role errors -> enable `tool_to_user` or `disable_tools`.
  - reasoning/thinking errors -> enable `strip_unsupported_params` / `codex_strip_reasoning`.
  - 413 -> reduce attachments or keep 64 MiB body limit warning.
  - 429 -> rate limit / quota warning.
  - 5xx/network -> provider availability warning.
- Keep this local-only; no automatic provider calls in v1.12.0 unless the user later asks.

Frontend requirements:

- Show failure clusters in Diagnostics and Logs.
- Show suggested strategy toggles without applying them automatically.

### 3. Provider Presets and Strategy Templates

Add built-in provider presets to reduce setup errors.

Backend requirements:

- Add built-in presets for:
  - OpenRouter
  - Volcengine Ark DeepSeek
  - DeepSeek official
  - Moonshot Kimi
  - Qwen DashScope
  - Xiaomi MiMo
  - Standard Anthropic-compatible provider
  - OpenAI-compatible Chat provider
- Each preset includes:
  - provider id
  - display name
  - base URLs
  - default auth header/scheme
  - recommended Claude alias
  - recommended Codex model
  - upstream model example
  - recommended compatibility policy fields
  - warnings
- Add Tauri commands:
  - `list_provider_presets`
  - `apply_provider_preset`
- Applying a preset creates or updates a provider and writes a provider compatibility policy.
- Applying a preset must not store an API key unless the user supplies one.
- Do not overwrite existing user API keys with empty values.

Frontend requirements:

- Add Provider Presets under Providers.
- Show preset intent, URLs, recommended model, warnings, and strategy flags.
- Add an Apply button that creates/updates the provider and refreshes all data.
- Keep manual Provider Strategy Overrides for advanced users.

### 4. Versioning and Documentation

- Bump all app metadata to `1.12.0`.
- Update README, README_EN, CHANGELOG, docs/project.md, and release notes.
- Add regression tests for report aggregation, failure recommendation mapping, and preset application safety.

## Non-Goals

- No silent app updater.
- No automatic `/Applications` overwrite.
- No real upstream request replay.
- No token-consuming health benchmark by default.
- No Apple Developer ID notarization changes.

## Safety Rules

- Redact API keys, Authorization headers, tokens, and long/binary payloads in exported bundles.
- Do not mutate Claude Code, Claude Desktop, Codex, or Codex++ configs from the Diagnostics page unless an existing explicit repair action is called.
- Do not auto-apply Provider Strategy Overrides based on diagnostics; only suggest actions.
- Preserve existing Codex++ `app.asar.unpacked`, `ElectronAsarIntegrity`, and re-signing safeguards.

## Implementation Plan

1. Add diagnostics and preset models.
2. Add backend aggregation helpers and Tauri commands.
3. Register commands in `lib.rs`.
4. Add frontend types, state, loading, Diagnostics page, and Provider Presets UI.
5. Add tests for diagnostic severity, failure recommendations, and preset application.
6. Bump version/docs and run validation.

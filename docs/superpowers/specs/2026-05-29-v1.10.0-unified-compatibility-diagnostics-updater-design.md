# Gateway Switch v1.10.0 Unified Compatibility, Diagnostics, and Updater Design

## Goal

Gateway Switch v1.10.0 completes the remaining compatibility roadmap in one release. It promotes the v1.9.0 diagnostics layer into a configurable compatibility control plane shared by Claude, Claude Code, and Codex, while adding safe request replay previews, one-click Claude Code repair, update checks, and installer guidance.

## Release Scope

### 1. Real Failed Request Diagnostics

Add a diagnostics workflow that starts from real failed gateway logs and produces a redacted replay preview.

Backend requirements:

- Extend request logging enough to identify failed requests by `request_id`, `claude_alias`, provider, model, status, duration, and error summary.
- Store a sanitized request/response snapshot when a gateway request fails with common diagnosis codes such as `400`, `413`, `429`, `500`, `502`, or timeout-like failures.
- Add a Tauri command that lists failed diagnostic candidates.
- Add a Tauri command that returns a redacted replay report:
  - original Claude or Codex request shape.
  - selected compatibility profile.
  - converted upstream payload.
  - redaction summary.
  - explanation of likely failure cause.
- Never send replay previews to upstream providers.
- Redact API keys, auth headers, long content, attachments, binary fields, and tool outputs.

Frontend requirements:

- Add a "Failed Request Diagnostics" panel on the Logs or Claude Code page.
- Let the user pick a failed request and inspect the redacted conversion path.
- Clearly mark previews as local-only and non-billable.

### 2. Editable Provider Strategy

Persist provider-level compatibility overrides while keeping automatic profiles as safe defaults.

Backend requirements:

- Add a `provider_compatibility_policies` table keyed by provider id.
- Store optional override booleans for:
  - `system_to_user`
  - `tool_to_user`
  - `disable_tools`
  - `strip_unsupported_params`
  - `direct_provider_safe`
  - `gateway_route_recommended`
  - `codex_disable_responses`
  - `codex_strict_tool_calls`
  - `codex_strip_reasoning`
- Store `notes`, `updated_at`, and `updated_by`.
- Merge rules:
  - automatic provider/model profile is the base.
  - explicit override values replace base values.
  - unset values inherit automatic behavior.
- Add list/get/upsert/reset Tauri commands.
- Use merged policies in Claude route diagnostics and payload conversion.

Frontend requirements:

- Add an editable Provider Strategy panel under providers or diagnostics.
- Show automatic value, override value, and effective value.
- Provide reset-to-auto per provider.
- Warn when a manual override makes Direct Provider appear safe for known incompatible endpoints.

### 3. One-Click Claude Code Repair

Detect unsafe Direct Provider bindings and repair them to Gateway Route.

Backend requirements:

- Add a repair command that:
  - inspects current Claude Code binding.
  - detects Direct Provider configurations for unsafe providers/models.
  - backs up existing environment/config state.
  - applies Gateway Route binding with the selected alias.
  - returns before/after state, backup path, and warnings.
- Reuse existing `claude_code_binding` functions instead of duplicating config writes.
- Keep Direct Provider blocked for known Volcengine Ark DeepSeek coding endpoints unless the user explicitly overrides provider policy and accepts warning state.

Frontend requirements:

- Show a repair action when diagnostics detects unsafe Direct Provider mode.
- Display what will change before running repair.
- Refresh Claude Code binding info after repair.

### 4. Codex Unified Compatibility Strategy

Bring Codex Gateway into the same Provider Compatibility Profile surface.

Backend requirements:

- Move shared strategy definitions into a common compatibility layer or expand the existing one.
- Add Codex-specific effective fields:
  - `codex_disable_responses`
  - `codex_strict_tool_calls`
  - `codex_strip_reasoning`
  - `codex_tool_call_mode`
  - `codex_prefer_chat_completions`
- Add Codex route diagnostics that explain whether a route uses Responses, Chat fallback, strict tool-call mode, or provider-specific cleanup.
- Wire merged provider policies into Codex request conversion where safe.
- Keep the 64 MiB body limit explicit for Codex and Claude gateways.

Frontend requirements:

- Add Codex route diagnostics near the existing Codex route/config panel.
- Show the same strategy id and effective flags used by Claude routes.

### 5. Update Checker

Add an in-app GitHub Release checker without performing silent app replacement.

Backend requirements:

- Add a small updater module that reads current version and checks the latest GitHub Release metadata.
- Return latest tag, current version, update availability, release URL, asset names, and a short summary.
- Network failures must be non-fatal and should produce an actionable warning.
- Do not auto-install in v1.10.0.

Frontend requirements:

- Add an update card in Settings.
- Show current version, latest version, release URL, and recommended action.
- Keep manual DMG install flow as the supported path.

### 6. Safe Install Overwrite Helper

Provide a safe installation assistant for replacing `/Applications/Gateway Switch.app`.

Backend requirements:

- Add an installation plan command that reports:
  - current executable path.
  - whether the app is running from `/Applications`.
  - whether it is running from a DMG or temporary path.
  - whether `/Applications/Gateway Switch.app` exists.
  - recommended manual steps.
- Add a helper command that opens `/Applications` and the current release artifact folder when available.
- Do not delete or overwrite `/Applications/Gateway Switch.app` silently.
- Do not attempt privileged writes without explicit user-driven macOS authorization.

Frontend requirements:

- Add a Safe Install card in Settings.
- Convert runtime source warnings into concrete install steps.

### 7. Provider Profile Matrix

Expand automatic profiles beyond the initial v1.9.0 set.

Initial profile targets:

- `standard_anthropic`
- `openai_chat_fallback`
- `volcengine_deepseek_coding`
- `openrouter_anthropic_or_chat`
- `xiaomi_mimo_chat`
- `deepseek_official_chat`
- `moonshot_kimi_chat`
- `qwen_dashscope_chat`
- `generic_user_assistant_chat`

Profile matching must be conservative:

- Prefer explicit URL/model/provider-name matching.
- Use Gateway Route when Anthropic compatibility is uncertain.
- Never mark Direct Provider safe unless the endpoint has a credible Anthropic-compatible URL.

## Data Model

### New Table: `provider_compatibility_policies`

Columns:

- `provider_id TEXT PRIMARY KEY`
- `system_to_user INTEGER`
- `tool_to_user INTEGER`
- `disable_tools INTEGER`
- `strip_unsupported_params INTEGER`
- `direct_provider_safe INTEGER`
- `gateway_route_recommended INTEGER`
- `codex_disable_responses INTEGER`
- `codex_strict_tool_calls INTEGER`
- `codex_strip_reasoning INTEGER`
- `notes TEXT`
- `updated_by TEXT NOT NULL DEFAULT 'user'`
- `updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP`

Nullable integer fields mean "inherit automatic profile".

### New Table: `request_diagnostic_snapshots`

Columns:

- `request_id TEXT PRIMARY KEY`
- `surface TEXT NOT NULL`
- `claude_alias TEXT`
- `provider_id TEXT`
- `upstream_model TEXT`
- `status_code INTEGER`
- `error_summary TEXT`
- `original_payload_json TEXT NOT NULL`
- `converted_payload_json TEXT`
- `redaction_summary TEXT NOT NULL`
- `created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP`

Snapshots must contain sanitized JSON only.

## Safety Rules

- Do not store raw API keys, Authorization headers, or large attachment contents.
- Do not replay any request over the network.
- Do not silently switch user configs without backup paths.
- Do not overwrite `/Applications/Gateway Switch.app` from inside the running app.
- Do not change existing provider behavior unless a conservative automatic profile already requires it or the user sets an override.
- Preserve existing Codex++ patch safeguards for `app.asar.unpacked`, `ElectronAsarIntegrity`, and ad-hoc signing.
